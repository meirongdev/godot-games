## 层 4:端到端证据摘录

4b 的倒计时序列是平局加速机制的完整证据链:

```
第 1 轮 · 存活 5 · 倒计时 3s
第 2 轮 · 存活 5 · 倒计时 2.5s  ← 连续平局 ×1,加速
第 3 轮 · 存活 5 · 倒计时 2s    ← 连续平局 ×2,加速
第 4 轮 · 存活 5 · 倒计时 1.5s  ← 连续平局 ×3,加速(触底)
第 5 轮 · 存活 5 · 倒计时 1.5s  ← 保持下限
第 6 轮 · 存活 2 · 倒计时 3s    ← 出现淘汰,重置
```

4c 三个场景:走神玩家被标记 AFK 并由服务端代出手势(之后胜负随机,不豁免淘汰);
切断一名玩家连接后其余玩家照常打到局终;房间 label 开局变 `playing`、局终回 `waiting`。

## 契约验证证据

```
"Found runtime modules","count":7,"modules":["games/init.lua","games/rps.lua",
  "lobby_rpc.lua","main.lua","room.lua","rules/room_rules.lua","rules/rps_rules.lua"]
Registered ... "id":"create_room" / "list_rooms" / "list_games"
```

顺带实证:未设 `runtime.lua_min_count` 时 Nakama 默认分配 **16 个 Lua VM**
(日志 `Allocating minimum Lua runtime pool, count:16`)——这正是部署契约 §3.2
要求成对设置 `lua_min_count/max_count` 的原因。
